## Current metric/display conventions

- Move Alignment is cosine similarity between the ECoT MOVE direction vector and the raw summed measured EE displacement over the executed chunk. No dead-band or sign quantization is applied to the action vector.
- Move Alignment is `T` when cosine ≥ 0.5 and `F` when cosine < 0.5. A missing directional MOVE is represented as `[0,0,0]` and assigned cosine 0 by review convention; unavailable measured displacement remains `N/A`.
- Rotation title labels are based on summed commanded rotation-vector components, independently thresholded at ±0.3 rad:
  - `rx`: roll about x
  - `ry`: pitch about y
  - `rz`: yaw about z
  - signs follow the right-hand rule.
- Target alignment uses simulator EE-to-resolved-target progress. Positive progress is aligned; zero/negative progress is not aligned; absent/unresolved targets are `N/A`.
- The action detail is intentionally compact:
  - summed measured translation;
  - ±3 mm convention;
  - summed commanded rotation vector;
  - ±0.3 rad per-component convention;
  - mean raw decoded gripper value;
  - displayed raw convention: `CLOSE=0, OPEN=+1`.
- The raw gripper average for the illustrated Task 0 query is about `0.9848`; do not replace it with the post-processed `−1.000` command.
- The report container now uses nearly the full browser width.
- The automatic Subtask column now groups consecutive identical subtask labels into periods. At each label change, the new query's before-scene and original ECoT subtask reasoning are shown as evidence for judging whether the previous subtask completed.
- A completed checkpoint contributes `+1` (or an editable multi-subtask count at the terminal checkpoint); an incomplete checkpoint contributes `−1`. The total is divided evenly over all queries in the preceding subtask period.
- A successful episode's final query is proposed to complete the explicitly stated current subtask plus every remaining numbered plan step. The current subtask's `+1` is distributed across its period; additional remaining subtasks are credited only to the final query. Thus Task 9 queries 7–11 receive `+1/6`, while query 12 receives `+1/6 + 1`; Task 0 query 5 receives `+4`.
- Initial checkpoint proposals treat a later recurrence of a subtask label as evidence that its earlier period failed. For Task 0, returning to `move to the cabinet` at query 4 makes the earlier queries 0–2 incomplete, assigning `−1/3` to each; the query-2 checkpoint shows `Not completed` and `0` completed subtasks.
- Each checkpoint panel is displayed on the last row of the subtask period it judges, while its scene and reasoning come from the following label-change query. The report script URL is versioned to prevent stale browser caching.
- Subtask-checkpoint rule version 3 invalidates checkpoint decisions stored under superseded scoring semantics, while preserving all other browser annotations. New human checkpoint decisions override the current proposals.
- For successful final checkpoints completing multiple subtasks, the evidence panel also shows the previous query's after-scene only when that query belongs to the same final subtask period. Task 9 therefore shows queries 11 and 12; Task 0's one-query final period shows only query 5.
- Each checkpoint image is the `after` scene from the last query of the subtask period being judged. The label-change summary and original ECoT subtask reasoning still come from the following query; captions identify both query numbers explicitly.
- Initial compact labels now quote the ECoT `MOVE`, summarize the actual executed action, judge approach reasoning from the resolved pre-action 3-D scene direction, and judge approach actions from observed target progress. The Subtask label and explanation use the period reward (including rollback and terminal bonuses), never the legacy per-query predicate score.
- Initial rationales are one compact line: reasoning judgment, actual-action judgment, numeric Move Alignment, target progress, and exact per-query subtask reward. Saved human labels continue to override these computed defaults.
